## 增益与交接

对同一席位和同一球路，仅切换操作者是否为 AI，验证普通球、加速、减速、大球、小球的回弹状态一致（4 席位 × 5 种状态）。检查包含旋转与变轨触发，而非仅比较比分。

四个席位分别可以获得同倍率长拍；含 AI 的左右两队均可以获得、保留和消耗护盾。真人掉线转 AI、检查点恢复和新房主接管后，已有长拍、连胜、护盾、旋转、变轨和速度不因身份而清除。

`src/base.html` 与 6.0.0 包中的同名源文件 SHA-256 完全相同：

```text
0bf06906d11e5d0ff2812ceceaeaa5ca31e40fd1c3f7e693be2367063c69d3aa
```

单人人机的无增益及难度逻辑保持在原基类中，回归集也验证了这些限制。团队新规则只在团队子类与团队房间逻辑中实施。

## 240 组落点对照

组合：左右来球 × 3 种旋转状态 × 5 种效果状态 × 8 组初始状态。其中一部分效果会在球抵达前到期。预判结果对照实际游戏 `sweepD4Ball` 的接触位置；测试临时移除其他球拍干扰并使用全高度接收拍，从而隔离“抵达指定接触面”的问题，不以是否挡住球代替落点正确性。

- 240 / 240 组均到达指定接触面。
- 最大落点差约 **2.46e-11 逻辑单位**，低于设置的 0.05 容差。这是确定性数值对照，不是实体玩家接球成功率。
- 同一批样例中，旧版部分提前量公式（未计旧版随机瞄准误差）的平均差约 **166.26 逻辑单位**。该比较只对应这些固定场景，不代表实战胜率变化。

随机变轨尚未发生时无法确定未来轨迹，测试没有把未来随机值提供给预判器；另以会抛错的随机函数检查 AI 规划不偷取随机结果。变化发生后由正常决策周期重新估计。

另外检查前后拍独立落点、越过前锋后的处理、上下分区守位、出球时预站位、45 / 25 ms 决策配置、移动上限、零速度与非法数值退出，以及预判不修改真实球状态。

## 连续逻辑压力测试

四根球拍均由 AI 控制，在上下协防和前后阵型各运行 **90 秒模拟时间**，含实际功能球和变轨逻辑。两种阵型分别记录 181 / 324 次击球，球和球拍保持有限数值，检查点校验正常。单步最大移动约 4.5833，符合 1100 / 240 上限。

这是加速执行的逻辑测试，不是 90 秒真实显示帧率采样，也没有把持续相互回球解释为对真人胜率提升。

## 软件渲染与平台边界

两组约 3.5 秒的 ASCII 主机采样（1 真人 + 3 AI）使用禁用 GPU 的 Chromium；每组 Canvas 上下文请求均为 0。具体提交间隔见 [PERFORMANCE.md](PERFORMANCE.md)。字符排版和绘制仍由浏览器完成，不承诺任意低端 CPU 恒定帧率。

**真实网络并未验收通过：** 本环境 `file://` 导航返回 `ERR_BLOCKED_BY_ADMINISTRATOR`，因此页面检查采用加载完整 HTML 内容的方式。原生 SDP 双端稳定，但两个连接均无 ICE 候选；生产邀请码生成正确拒绝“没有可用的连接地址”。记录见 `validation/native_environment.json`。没有删除候选检查或修改浏览器策略来伪造连接成功。

未完成实体手机、本地文件导航、真实多设备局域网、公网 PeerJS / TURN、线上 Pages 及真实网络房主迁移的端到端验收。协议中的“连接”由明确的消息转发替身建立，不能替代上述实测。

## 复跑

运行游戏无需测试依赖。开发者可按 README 安装 Playwright，并在根目录执行：

```sh
python tools/build.py
node --check validation/compiled.js
python tools/test_team_ai.py
python tools/test_team_ui.py
python tools/regression.py
python tools/test_team_protocol.py
python tools/test_native_environment.py
```

协议套件建议单独运行并给予足够执行时间。性能结果受宿主负载影响；测试会覆盖本次原始结果，需留存时先复制 `validation/`。
