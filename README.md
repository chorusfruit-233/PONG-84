# PONG-84 🕹️

一款复古风格的单文件浏览器乒乓球游戏，支持 CRT 图形画面与 ASCII 纯字符画面、人机对战、同屏双人和 WebRTC 联机。

保存 `index.html` 后即可在浏览器中打开，也可以部署到 GitHub Pages。游戏前端无需安装依赖或执行构建；本地对战不需要服务器，联机可选择手动交换连接码或使用 4 位云房间码。

[快速开始](#快速开始) · [操作说明](#操作说明) · [联机指南](#联机指南) · [GitHub Pages 部署](#github-pages-部署) · [常见问题](#常见问题) · [开发说明](#开发说明)

> **关于“纯前端”**：手动 P2P 不需要信令服务器，但跨网络连接仍可能需要 STUN / TURN。GitHub Pages 只托管网页，不会自动提供信令或中继服务。

## 功能概览

| 功能 | 说明 |
| --- | --- |
| 单文件运行 | HTML、样式、游戏逻辑、音效生成及手动 P2P 代码集中在 `index.html` 中。 |
| 两种画面 | CRT 图形渲染与 ASCII 字符渲染，可在对局中切换。 |
| 四种游戏模式 | 人机对战、同屏双人、同屏双人计时赛、双设备联机对战。 |
| 键盘与触屏 | 支持键盘移动、拖动球拍、同屏双指操作和全屏显示。 |
| 功能球与回球效果 | 加速、减速、大球、小球、长拍，以及变轨、旋转回球和连得分护盾。 |
| 人机增益限制 | 电脑不获得长拍、连得分护盾或临时移速增益；功能球按有利于玩家的方向生效。 |
| 两种联机入口 | 原生 WebRTC 手动连接，以及基于 PeerJS 的 4 位云房间码。 |
| 网络配置与诊断 | 支持自定义 STUN、TURN、PeerServer，显示连接状态、往返延迟及可识别的直连／中继路径。 |

## 快速开始

将游戏文件保存为 `index.html`，用完整浏览器打开，选择游戏模式并点击“开始游戏”。倒计时结束后，轮到发球的一方按发球键；触屏设备可拖动调整位置后松手发球。

本地人机、同屏双人和计时赛可以离线运行，不需要 Node.js、npm 或本地开发服务器。不要把聊天软件的附件预览、GitHub 源码页面当作游戏运行页面；需要打开实际 HTML 文件或已发布的网站。

浏览器需要启用 JavaScript。联机还需要可用的 WebRTC 数据通道；本地文件访问、全屏、剪贴板及设备网络策略可能因浏览器而异。手机和平板适合横屏操作。

### 游戏模式

| 模式 | 对战形式 | 结束条件 |
| --- | --- | --- |
| 人机对战 | 玩家控制左拍，电脑控制右拍；提供简单、普通、困难、地狱四档难度。 | 先达到目标比分的一方获胜。 |
| 双人对战 | 两人在同一设备上分别控制左右球拍。 | 先达到目标比分的一方获胜。 |
| 计时赛 | 同屏双人对战，可选 30 秒、1 分钟或 2 分钟。 | 时间结束时比较比分，支持平局。 |
| 联机对战 | 两台设备一对一对战；房主控制左拍，加入者控制右拍。 | 使用房主设置的目标比分，由房主开始比赛。 |

目标比分提供 5、7、11、15、21 分选项，也支持自定义 1–99 分，默认 11 分。

## 操作说明

### 键盘

| 场景 | 移动 | 发球 |
| --- | --- | --- |
| 人机对战 | `W` / `S` 或 `↑` / `↓` | 轮到玩家时按 `空格` 或 `Enter`。 |
| 同屏双人／计时赛：左方 | `W` / `S` | `空格`。 |
| 同屏双人／计时赛：右方 | `↑` / `↓` | `Enter`。 |
| 联机对战：双方各自的设备 | `W` / `S` 或 `↑` / `↓` | 轮到自己时按 `空格` 或 `Enter`。 |

`R` 切换图形／ASCII 画面，`F` 切换全屏。非联机模式下，`P` 或 `Esc` 暂停／继续；全屏状态下的 `Esc` 优先用于退出全屏。

发球只在轮到自己时有效。对局中的空格／回车不会触发“开始游戏”或重置比分，长按也不会重复发球。

### 触屏

人机和联机模式在游戏区域上下拖动即可控制自己的球拍；同屏双人和计时赛的左右半屏分别控制左右球拍，支持双指同时操作。轮到自己发球时，拖动调整位置后松手发球。

全屏、渲染切换和暂停也提供界面按钮。联机不支持单方暂停，可使用右上角“退出联机”结束连接。

## 画面与游戏机制

### CRT 与 ASCII

CRT 模式提供绿色、琥珀色、白色、蓝色四种磷光主题，以及扫描线、拖尾等视觉效果。

ASCII 模式将场地、球拍、球、比分和状态写入字符网格，而不是在图形画面上叠加字符滤镜。游戏画面使用可打印 ASCII 字符，因此画面内的提示采用英文；菜单和按钮仍保留中文网页控件。

两种模式使用相同的物理规则和控制坐标。切换画面不会重新开始比赛，也不会清空比分或当前效果；联机双方可以分别选择自己的显示方式。

### 功能球与护盾

随机功能包括加速、减速、大球、小球和长拍。首次功能效果在累计对打 1–2 秒后触发；效果结束或被清除后，下一次等待为 1.5–3 秒。等待发球和暂停不计入功能效果的等待时间。

变轨与旋转属于回球机制：符合条件的回球有 24% 的概率启动变轨，击球位置也会影响反弹角度和旋转。连续得到 3 分可获得一次护盾，用于抵消下一次本应失分的情况；电脑不获得该护盾。

### 人机模式的增益规则

在人机模式中，加速和小球仅在球攻向电脑时生效；减速和大球仅在球回向玩家时生效；长拍只作用于玩家。电脑回球不继承玩家的加速、小球、旋转或变轨强化，电脑移动也不获得临时速度加成。

四档难度仍保留各自的基础移动速度、球拍长度、预测与失误参数。这里的“无增益”指禁止对局中的额外强化，不表示所有难度使用相同的基础参数。同屏双人、计时赛和联机模式允许双方获得效果与护盾。

## 联机指南

双方使用同一版本的游戏。联机既可以从本地 HTML 发起，也可以从 GitHub Pages 等静态网页发起；房主必须保持页面打开。

### 选择联机方式

| 方式 | 交换连接信息 | 外部依赖与适用条件 |
| --- | --- | --- |
| 手动 P2P＋同一局域网 | 双方传递邀请码和回应码。 | 不加载 PeerJS，不使用云信令、STUN 或 TURN；两台设备必须能够互通。 |
| 手动 P2P＋跨网络 | 双方传递邀请码和回应码。 | 不使用云信令；使用配置的 STUN，无法直连时可能需要有效 TURN。 |
| 云端 4 位房间码 | 输入房间码，由信令服务自动协商。 | 按需加载 PeerJS，连接公共或自建 PeerServer；直连／中继另由网络设置决定。 |

云房间即使选择“同一局域网”，也仍然依赖组件下载和信令服务。只有“手动 P2P＋同一局域网”这一组合不需要游戏外部网络服务；通过聊天工具传码产生的网络访问不属于游戏内部连接。

### 方式一：手动 P2P

双方选择 **联机对战 → 本地 P2P · 手动连接**，并选择相同的网络范围。

同一 Wi-Fi 或可互通的局域网选择“同一局域网 · 不使用 STUN/TURN”；不同网络选择“跨网络 · STUN / 可选 TURN”。同一 Wi-Fi 并不保证设备互通，访客网络、接入点隔离或防火墙仍可能阻止连接。

| 步骤 | 操作者 | 操作 |
| --- | --- | --- |
| 1 | 房主 | 点击“我是房主 · 生成邀请”，等待生成完整邀请码，并发送给对方。 |
| 2 | 加入者 | 点击“我是加入者 · 粘贴邀请”，粘贴邀请码，再点击“生成回应码”。 |
| 3 | 加入者 | 将生成的回应码发回房主，保留当前页面。 |
| 4 | 房主 | 粘贴回应码，点击“确认回应并连接”。 |
| 5 | 双方 | 等待连接成功，再由房主点击“开始游戏”。 |

连接码以 `P84V2.` 开头，与 4 位云房间码不同。**必须完成“邀请 → 回应 → 房主确认”整个流程。**

可使用“复制连接码”，也可“保存为文件”后发送给对方，再通过“从文件读取”导入。读取文件后仍需点击相应的确认按钮；文件大小上限为 64 KB（65,536 字节）。

生成连接码后不要刷新、关闭页面或重复生成。取消、刷新或重新生成后，应使用新邀请码重新完成协商，不要混用旧回应码。连接码只发给本次对手，不要公开发布。

### 方式二：4 位云房间码

双方选择 **联机对战 → 云端联机 · 4 位房间码**。房主点击“创建云端房间”，将 4 位号码告知对方；加入者点击“输入房间码加入”，输入号码并加入。连接成功后由房主开始游戏。

云模式使用 PeerJS 1.5.5，创建或加入房间时才从 unpkg 加载，失败后尝试 jsDelivr；默认连接 PeerJS 公共信令服务。PeerServer 负责连接协商，并不代替 TURN。[参见 PeerServer 官方说明][peer-server]

默认房间分组为 `pong84-public-v2`。双方须使用相同的信令服务、端口、路径、服务 key 和房间分组。房间 ID 不按网页域名划分，因此本地文件端与静态网站端不会仅因打开地址不同而被分到不同房间空间。

**4 位房间码不是密码，房间分组也不是访问控制。** 当前联机适合熟人之间的一对一对战，不提供账号认证、房间密码或公开自动匹配。

### 连接诊断与重连

展开“连接诊断 / 联机失败怎么办”，可查看 WebRTC 可用性、连接状态、地址收集状态、数据通道、往返延迟，以及浏览器能够识别的实际连接路径。

“浏览器直连”与“TURN 中继”是两种不同路径；尚未获得足够统计信息时显示“尚未确定”，不能据此认定已经直连。

对局中应保持双方页面在前台。锁屏、长时间切到后台或切换网络可能中断对战。当前没有完整的断线续局机制，持续断线后应退出并重新连接。

## GitHub Pages 部署

### 发布静态游戏

将文件直接放在仓库根目录，入口文件命名为 `index.html`。不要只上传压缩包。

```text
.
├── index.html       # 完整游戏入口
├── README.md        # 项目说明
├── .nojekyll        # 空文件，用于跳过 Jekyll 处理
└── TEST_REPORT.md   # 可选：测试记录，不参与游戏运行
```

在仓库中打开 **Settings → Pages → Build and deployment**，设置发布来源：

```text
Source:  Deploy from a branch
Branch:  main
Folder:  / (root)
```

若文件位于其他分支，选择实际分支。点击 **Save** 后查看部署结果，使用 Pages 设置页显示的真实网址访问游戏；部署失败时检查仓库的 Actions 日志。本项目无需 npm 构建，也无需额外编写构建工作流。[发布配置说明][pages-publish]

在 Pages 设置中启用 **Enforce HTTPS**。[HTTPS 配置说明][pages-https]

### Pages 上如何联机

**发布网页和建立联机是两件事。** Pages 提供静态 HTML、CSS 和 JavaScript，不提供常驻的 PeerServer 或 TURN 服务。[GitHub Pages 说明][pages-about]

| 使用方式 | 需要另外部署什么 |
| --- | --- |
| 本地对战／同屏双人 | 不需要联机服务。 |
| 手动 P2P | 不需要信令服务器；跨网络不能直连时仍需配置可用 TURN。 |
| 公共 4 位云房间 | 不需要自行部署信令，但依赖公共 PeerServer 和组件 CDN；部分网络仍需 TURN。 |
| 自行维护公网联机服务 | 在独立服务器或合适的平台运行 PeerServer，并按网络需求提供 TURN。 |

手动交换连接码替代的是自动信令，不是网络穿透。已有房间码或已完成 SDP 交换，也不代表 WebRTC 数据通道已经接通。[WebRTC 连接流程][webrtc-connections]

### 自建信令与 TURN

展开游戏中的 **高级网络设置：STUN / TURN / 自建信令**。设置只在新连接时生效，更改后需取消旧连接并重新创建／加入。

自建信令必须是兼容 PeerJS 的 PeerServer，不能填写任意 WebSocket 服务，也不能直接填写 GitHub Pages 域名。下面仅示意已部署服务的客户端配置，不表示这些示例地址真实可用：

| 字段 | 示例 |
| --- | --- |
| 自建 PeerServer 域名 | `signal.example.com`，不含协议头、端口或路径。 |
| 端口 | `443`。 |
| 路径 | `/pong84`，与实际服务路径一致。 |
| 服务 key | `peerjs`，或服务端配置的值；它不是安全密码。 |
| 房间分组 | 双方相同，例如 `my-pong84-v2`。 |
| 安全信令 | HTTPS 网页保持启用，服务端提供有效的 HTTPS / WSS 入口。 |

PeerServer 的部署需另外处理证书、反向代理和 WebSocket 转发；当前仓库不包含这些服务。[PeerServer 部署说明][peer-server]

TURN 用于直接连接不可行时转发数据，必须填写实际可用的服务地址和对应凭据。以下同样只是格式示例：[TURN 说明][webrtc-turn]

```text
TURN 地址：
turn:turn.example.com:3478?transport=udp
turns:turn.example.com:5349?transport=tcp

TURN 用户名：服务提供方签发的用户名
TURN 密码 / 临时凭据：与该用户名匹配的有效凭据
```

只有配置了有效 TURN 后才勾选“强制 TURN 中继”。该选项可用于排查直连问题，但不能与“同一局域网 · 不使用 STUN/TURN”同时使用。

当前只支持手工填写 TURN 凭据，未附带 TURN 服务或自动签发后台。公开服务可通过独立后端签发短期凭据；长期服务密钥保留在后端，不写入网页。以 Cloudflare TURN 为例，官方要求将长期 TURN key 留在服务端，并为客户端生成短期凭据。[凭据管理说明][turn-credentials]

自建 PeerServer 不会取消客户端的 CDN 依赖。完全自主托管时，还需自行托管对应版本的 PeerJS，并修改 `loadPeerLibrary()` 中的加载地址。

## 安全与隐私

游戏不需要摄像头或麦克风权限。常规游戏设置保存在浏览器 `localStorage` 中；网络设置只保留在当前页面内存。TURN 用户名和密码不会写入本地存储、连接码或导出的连接码文件。

**不要将长期 TURN 密码、服务商 API Token 或凭据签发密钥提交到公开仓库。** 存在页面内存中的信息也不对当前设备使用者保密。

邀请码和回应码包含会话协商信息及候选连接地址，只应通过可信渠道交给当前对手。连接码的完整性校验用于发现内容损坏，不是身份认证或加密签名。公开反馈问题时，删除完整连接码、凭据和个人网络地址。

使用云房间、STUN 或 TURN 时，浏览器会访问相应外部服务；“纯前端”不表示所有模式均无外部网络请求。联机采用房主计算游戏状态的方式，不提供竞技级反作弊保证。

## 常见问题

| 现象 | 处理方式 |
| --- | --- |
| HTML 显示为源码或附件预览 | 将文件保存后在完整浏览器中打开，或访问实际 Pages 地址。 |
| 同一 Wi-Fi 仍连不上 | 检查是否为访客网络、是否启用设备隔离，以及设备防火墙和浏览器策略。 |
| 邀请码／回应码已生成，但未连接 | 确认房主完成最后的“确认回应并连接”，双方页面未刷新，并检查连接诊断。 |
| 提示回应码不属于本次邀请 | 取消旧连接，由房主重新生成邀请，完整重做交换流程。 |
| 跨网络地址收集或连接超时 | 检查 STUN / TURN 是否可达、凭据是否有效；必要时配置 TURN。 |
| 复制按钮不可用 | 手动选中全文复制，或使用“保存为文件／从文件读取”。 |
| 云联机组件下载失败 | 检查 CDN 访问；可切换到不依赖 PeerJS 的手动 P2P。 |
| 提示云房间不存在 | 检查号码、版本、信令服务及房间分组，确认房主未离开。 |
| 找到房间但无法开始联机 | 信令成功不等于数据通道成功，继续检查网络、STUN / TURN。 |
| 自建信令在 Pages 页面连接失败 | 检查 HTTPS / WSS、有效证书、服务路径和反向代理的 WebSocket 转发。 |
| 球拍或比分不再更新 | 让双方页面保持前台，查看延迟和通道状态；持续断线后重新连接。 |
| Pages 访问失败或仍显示旧版 | 检查发布分支、目录、入口文件和 Actions 部署结果，再重新加载页面。 |

更换网页托管地址本身不会解决 NAT 或中继问题。当前发布资料中的测试不包含真实双设备、跨运营商网络、TURN 和线上 GitHub Pages 的端到端实测；实际可用性需在目标浏览器和网络中验证。

## 开发说明

### 代码组织

游戏采用原生 HTML、CSS 和 JavaScript。主要模块均位于 `index.html`：

| 模块 | 职责 |
| --- | --- |
| `AudioEngine` | 使用 Web Audio 生成游戏音效。 |
| `InputManager` | 处理键盘、触屏和发球输入。 |
| `OnlinePeer` | 管理原生 WebRTC／PeerJS 连接、消息、连接码与诊断。 |
| `AsciiRenderer` | 将游戏状态转换成 ASCII 字符画面。 |
| `PongGame` | 处理物理、碰撞、比分、效果、图形渲染与联机状态同步。 |
| `UIController` | 管理菜单、显示设置、全屏和联机操作界面。 |

房主计算球的运动、碰撞、得分与功能效果；加入者发送控制输入，并使用本地球拍预测和房主状态校正。状态与输入的目标同步频率均为 60 Hz，不等于任何设备和网络下都能达到该频率。

### 常用参数

| 配置项 | 当前值／用途 |
| --- | --- |
| `WORLD` | 逻辑场地为 `960 × 540`。 |
| `FIXED_DT` | 物理步长为 `1 / 240` 秒。 |
| `PC_PADDLE_SPEED` | 真人键盘球拍速度为 `1100` 逻辑单位／秒，不用于提升电脑移速。 |
| `BALL_TUNING` | 基础球速、最大球速和击球加速参数。 |
| `EFFECT_TIMING` | 首次效果等待 `1–2` 秒，后续间隔 `1.5–3` 秒。 |
| `CURVE_CHANCE` | 符合条件的回球触发变轨的概率为 `0.24`。 |
| `ASCII_GRID` | 默认字符网格为 `160 × 45`，紧凑画面使用 `128 × 36`。 |
| `DIFFICULTY` | 电脑的基础移动、预测、球拍和失误参数。 |
| `NETWORK_STATE_HZ` / `NETWORK_INPUT_HZ` | 状态／输入的目标发送频率，均为 `60`。 |

修改物理或联机协议后，应让双方使用同一版本，检查发球、得分、护盾、再来一局、退出联机及渲染切换，避免只验证单端显示。
